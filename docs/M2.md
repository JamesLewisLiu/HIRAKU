# M2: kernel glue, interrupts, devices (2026-10-11)

## What runs

`hiraku-bm3final` boots beatmania III The Final from its entry point. The boot assembly is interpreted; from `main` on, the recompiled code runs natively on one host fiber per guest thread. The game draws its STARTUP self-test:

| Check | Result | Provided by |
|---|---|---|
| I/O | OK | board inputs (`runtime/firebeat/board.cpp`) |
| IBTN | OK | DS1991 protocol on the 403 serial port (`cpu403.cpp` + board). The serial number `C01309672` matches MAME |
| VER | OK | |
| BACKUP | OK | RTC65271 + 4 KiB NVRAM (`dev/rtc65271.*`, MAME port), default image from the ROM set |
| RTC | OK | clock on virtual time, fixed start date (reproducible) |
| SPU | **E704** | the sound board (68000 + RF5C400) is M4 |
| HDD | — | behind the SPU (its ATA bus) |
| FDD | OK | FDC37C665GT / µPD765 subset with an empty drive (`dev/fdc.*`) |
| ST224 | OK | 16550 MIDI UART with transmitter-empty interrupts |
| ATAPI | OK | ATA/ATAPI CD-ROM, PIO (`dev/ata.*`) on the user's disc image |
| ISO | OK | ISO9660 read through the game's own driver |

## How it was matched

Each device was built from MAME's source or behaviour, then corrected against MAME's MMIO trace (`oracle/align.py`):
- **Whole stream:** 23,707 records identical up to the first SPU mailbox read. The comparison drops the status LEDs and VBlank-handler accesses (interrupt timing) and ignores RTC read data (host clock).
- **Floppy check:** 63 records identical. This fixed the drive-busy bits in MSR and the cancelling of reset polling interrupts by CONFIGURE.
- **ST-224 MIDI handshake:** 128 records identical. This fixed the FIFO bits in IIR, and the THR→TSR transfer that re-arms THRE immediately.

## Things the real code needed

- **Time base aliases.** User-mode delay loops read TBHU/TBLU (SPR 0x3CC/0x3CD).
- **Full-word trace reads.** MAME's tap reports a 32-bit device's whole register even for a 16-bit read. The runtime's tracer does the same for the GCU.
- **Hidden entry points.** Code reached only through addresses built in code (`lis`/`addi`). The exporter now promotes every decoded instruction nothing falls into (29 in bm3final).
- **Interrupts while interpreting.** An interrupt taken between interpreted instructions must not be mistaken for a branch-to-self hang.
- **Safe shadow checks.** The native half of a check must bail out *before* touching a device or the time base. Device state can't be rolled back, and doing it afterwards perturbed the run.

## Performance

30 virtual seconds take about 10 s on this machine.
- Most of it is interpreted: the boot RAM clear (356M instructions) and the vector glue, at about 90 instructions × 2.4M exceptions.
- The recompiled game code itself is negligible.
- `--window` paces to real time at about 50% of one core.
- Recompiling the vector code is the next step (M9).

## Not in M2

- SPU (M4), YMZ280B and CDDA (ParaPara, M8), the spectrum analyser (returns silence).
- The second GCU (Keyboardmania).
- Network UART traffic (the UART is present and idle).
- PPC DMA is implemented for software memory-to-memory transfers only. Other modes are a fatal error, so any use will show up.
