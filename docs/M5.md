# M5: a playable session (2026-10-11)

## Done

- **A full game loop runs natively** (scripted, 12.5 minutes of game time, no fallbacks):
  1. boot and self-test;
  2. attract mode with its demo plays and rankings;
  3. coins, mode select, practice stage (tutorial), stage 2;
  4. stage failed, results, CONTINUE countdown, DJ LEVEL, game over;
  5. back to attract.

  The sound board loaded 154 MB of samples and played 1,654 keysounds.
- **Real-time mode (`--window`):**
  - audio-clock pacing, 8 ms queue target, 128-frame device buffer requested;
  - controls polled every few ms;
  - keyboard and joystick bindings (hot-plug, analog or key turntable);
  - fullscreen, Tab fast-forward;
  - clean exit and NVRAM save on Esc, window close and Ctrl-C.

  See `docs/PLAY.md`.
- **Latency, measured** (from a P1 key press to the RF5C400 key-on of its keysound, virtual time):
  - **The game reads its keys once per video frame (60 Hz).** In MAME's trace the key-sensor reads come in a burst, then 16.5 ms of nothing.
  - A press therefore waits 0–16.7 ms for the next scan, plus about 2 ms for the command to reach the sound board.
  - **Hands-on session (302 presses): mean 9.5 ms, spread evenly over 2–20 ms.** This is the original game's latency; a real cabinet has the same.
  - *Correction:* an earlier figure of 3.5 ms came from the input script. It changes inputs exactly at frame boundaries, just before each scan, so it only ever measured the best case.
  - On top of this comes the host: the audio queue (8 ms), the device buffer, and the sound server.
- **NVRAM persistence:** loaded and saved per machine (`~/.local/share/hiraku/<game>`; `--nvram`). Scripted runs start from the ROM defaults so they stay reproducible.

## Audio stalls (after the first hands-on test)

**Report:** crackles at 8 ms, much worse at 4 ms. Profiling (a built-in stall profiler, plus a SIGPROF sampler: `HK_PROFILE=1` writes `hk-profile.txt`) showed host work arriving in bursts larger than the queue. The fixes:

1. **The GCU blitter and compositor were over 40% of host time,** in a burst at each display-list kick. They now use direct 16-bit VRAM access and a 1:1 blit fast path, and are still bit-exact against MAME (28/28 replayed frames).
2. **Exception vectors run natively.** They were interpreted (about 90 instructions × ~72k exceptions/s). The exporter now makes the 4xx vectors functions, and `rfi`/`rfci` compile to a return through SRR0/SRR1 (SRR2/SRR3).
3. **The boot code runs natively too.** Nothing is interpreted any more after start (it was 356M instructions at boot).
4. **Virtual time is charged per executed instruction** (`HK_TICK` per straight-line run), not a flat cost per poll. Yield loops no longer spin far more often than on hardware, and the timeline moved much closer to MAME's (the song starts 1–2 frames from MAME instead of 13).
5. **The audio queue tunes itself** (+1 ms per underrun, up to 30 ms).

**Result** (headless, real-time dummy audio device, 88 s including song load):

| Setting | Before | After |
|---|---|---|
| 4 ms queue: empty-queue events | 7,185 | 1,393 |
| 8 ms queue: empty-queue events | (not measured) | 17 |
| Self-tuning from 8 ms | — | 4 events, settled at 12 ms |
| Chunks needing > 4 ms of host work | 4,390 | 13 |

Shadow mode is still clean (183 identical, 0 mismatches).

## Found along the way

- **No writes in these sessions.** beatmania III The Final wrote nothing persistent in these sessions, in MAME or in HIRAKU: RTC RAM and flash are unchanged and MAME made no HDD diff file. It writes NVRAM only when settings or rankings change, which none of these sessions did.
- **Latency outliers above about 20 ms** (a few per session) are key-ons not caused by the press, such as BGM or a release.

## Needs a person at the controls

- How the latency feels on real audio hardware with PipeWire. A low `PIPEWIRE_LATENCY` is likely needed.
- Real controllers' button and axis numbering. The defaults assume buttons 0–4 for keys, axis 0 for the turntable.
- **Name entry:** reaching it needs a ranking-worthy score, which the scripted runs don't play for.
